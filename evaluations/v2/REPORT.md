## 新版执行失败的原因（这次改动的缺陷）

- **现象**：新版有 127 次模型调用结果为 UNKNOWN（传输超时），其中聊天 70 次、记忆抽取 25 次、记忆审核 32 次。旧版是 0 次。
- **原因**：本地嵌入和重排是在异步事件循环里同步跑的 CPU 计算。6 个人物并发时，每题会阻塞事件循环约 2–5 秒，同时在等待的模型请求就超时了。
- **为什么记成失败**：超时的请求可能已经计费，Core 按设计不重放，所以这些题记为失败。
- **连带影响**：抽取和审核批次超时后，对应的事实没有进入长期记忆。这很可能就是多跳题 Q24（新版 3/24，旧版 21/24）退步的主要原因：值班表文件里的事实没被记下来。
- **生产环境同样受影响**：这段 CPU 计算也会阻塞 API 进程里的其他请求。
