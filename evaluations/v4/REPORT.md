## 主要问题

### T04 退步（新 Core 6/20）
事实“工作日绿茶、周末红茶”已被抽取成记忆，但记忆检索的分数下限把它挡在候选池外（开不开重排都一样）。旧 Core 是靠情节续接把那几轮带进 prompt；新 Core 先放原文召回、续接只用剩下的配额，那几轮被挤掉了。
可能的修法：召回命中轮次的相邻轮扩展，或者给续接保留最低配额。这些都是看了第 4 轮结果才想到的，要先离线验证，再用一个新题库验收，不能拿本轮分数当证据。

### T01 在 0 天全错（新 Core 0/5，3 天以后 15/15）
五个回答都说清单“读到手套（大号）就断了”。当前轮和最近历史里的附件仍然按固定字数截断，目标行在第 50 行之后；而原文召回（3 天以后）会用 `focus()` 按行挑出相关行，所以能答对。修法是把同样的按行聚焦用到当前轮和最近历史的附件上。

### 离线事实召回指标偏松
`eval_recall.py` 的事实召回只要返回的记忆引用了题目的任一来源事件就算命中，所以报出 360/360，掩盖了 T04 的漏检。应改为要求覆盖题目需要的字段。
